# app-ui

## summary
Unit app-ui is the web front end of the Tauri shell: three files, app.js (448 lines), index.html (308 lines) and style.css (242 lines), all under C:/Yanivs/shareCtrlScreen/native/app/ui/. app.js is a classic script with module-level mutable state (state, config, incomingFrom, passwordFrom, cancelCountdown at app.js:26-30). It drives a 7-state machine (STATES at app.js:16-24: OFFLINE, READY, REQUESTING, PASSWORD_PROMPT, INCOMING, HOST_ACTIVE, VIEW_ACTIVE). setState (app.js:35-39) validates and calls render() (app.js:41-62), which toggles .hidden on three screens (screen-home, screen-host, screen-view) and three modals (modal-requesting, modal-password, modal-incoming), force-hides modal-link outside live sessions (app.js:56-58), and gates btn-connect on READY plus a valid UUID (app.js:61).

All real work (WebRTC, signaling, capture, the native D3D11 child surface, keyboard capture, clipboard and file handling) lives in the Rust engine. The UI talks to it only through window.__TAURI__.core.invoke (app.js:10) and window.__TAURI__.event.listen (app.js:11). Commands invoked: get_config (app.js:111), clear_recents (app.js:160), save_settings with a patch object (app.js:224), set_video_visible {visible} (app.js:199, 250), request_refresh (app.js:242), connect_to {id} (app.js:283), end_session (app.js:288, 342, 343, 347), submit_password {host,password,remember} (app.js:301), approve {from,decision} with decision view|control|deny (app.js:330), set_permission {value} (app.js:340), get_server_status (app.js:439). Events listened: server-status {status: connected|reconnecting} (app.js:351), approval-request {from} (app.js:368), password-required {from} (app.js:380), role-changed {role: host|viewer|other, peer, permission} (app.js:391), toast {message} (app.js:414), link-trouble {secsLeft} (app.js:419), link-restored (app.js:425). The only timers in the UI are 1 s client-side countdown mirrors (countdown helper app.js:90-102) for REQUESTING (30 s, app.js:279, 309) and INCOMING (30 s, app.js:374). The INCOMING comment (app.js:373) says the Rust decider is the authority and auto-denies at 30 s. The link-trouble countdown is driven entirely by the engine's secsLeft.

index.html is static markup with the same ids and class vocabulary as the original Electron renderer (index.html:9-14). It declares the home, host and view screens, the REQUESTING, PASSWORD, INCOMING, LINK and SETTINGS modals, and the toast container. style.css is a dark-theme token set (:root, style.css:3-15) with a font stack of "Segoe UI", system-ui and Consolas/"Cascadia Mono" monospace. Nothing in app-ui branches on OS at runtime. The platform coupling is in the engine contracts and in Windows-specific copy.

A non-Tauri host needs an adapter exposing invoke(cmd, args) returning a Promise and listen(name, cb) returning a Promise of an unlisten function (the UI never calls unlisten; app.js:351-425).

- The #video-wrap element (index.html:108) is the only handle the engine needs for the native surface. Its layout is governed by style.css:174-182 (flex:1, black background, overflow hidden). A port keeps the element and lets the engine map its surface to the element's bounding rect.

## gotchas
- set_video_visible(false) must complete before a modal paints, since the native surface sits above the WebView. app.js:246-248 states the reason: opening the dialog first leaves it underneath the video, sliced to the hover strip.
- closeSettings re-shows the native video only if state === 'VIEW_ACTIVE' (app.js:199). Settings can be opened from home (index.html:25, btn-settings) and from the view bar (index.html:104, btn-view-settings). There is no settings button in the host header (index.html:62-69), so the host screen never opens settings. Keep this invariant when porting screens.
- render() hides modal-link on every state change outside VIEW_ACTIVE/HOST_ACTIVE (app.js:54-58; comment at app.js:55 says only the engine may show it). link-trouble events are ignored in non-session states (app.js:420).
- Password save semantics: '' clears the saved password only when the clear checkbox is ticked (app.js:217-218). Otherwise an empty field means unchanged (app.js:219-221). The placeholder reads '(unchanged)' or '(none set)' from hasPassword (app.js:175).
- btn-connect is disabled unless state is READY and the input is a v4 UUID (app.js:61; regex app.js:32). The invalid-ID hint appears only for non-empty input (app.js:268).
- Countdown timers: REQUESTING (app.js:279-282, 309-312) and INCOMING (app.js:374-377) use a 1 s setInterval that moves to READY on expiry. stopCountdown (app.js:104-107) must run before any state change that could leave a stale timer, otherwise a stale tick can call setState('READY') during a live session. role-changed calls stopCountdown (app.js:393).
- approve decision 'deny' returns to READY immediately (app.js:332). view and control leave the state unchanged and wait for role-changed. incomingFrom is cleared on every decision (app.js:331).
- cancelPassword and the Escape key path (app.js:293-297, 317-325) do not call end_session; cancelling the prompt returns to READY locally, and the engine is not told. Confirm the engine tolerates a dropped password prompt.
- btn-cancel-request calls end_session and sets READY locally (app.js:286-290). Errors from connect_to (app.js:283), submit_password (app.js:301), approve (app.js:330), set_permission (app.js:340) and end_session (app.js:288, 342, 343, 347) are not caught; the calls are not awaited. A rejected connect_to leaves the UI in REQUESTING until the 30 s timeout.
- Unpopulated control: #set-share-display (index.html:291-295) contains only the 'Primary monitor' option. Nothing in app.js populates it (app.js:179 only sets .value), so a saved shareDisplayId cannot be selected unless something else adds options. A macOS or Linux port needs a display-enumeration source; none exists in app-ui.
- Dead CSS: style.css:183 targets #video, an element index.html no longer contains (index.html:13-14). style.css:184 (.video-wrap.control cursor none) is never applied because app.js only sets the badge class (app.js:404-406), never 'control' on #video-wrap.
- Toasts are removed after a fixed 4000 ms (app.js:86), not de-duplicated, so repeated engine errors stack.
- The Connect input uses the datalist recent-ids (index.html:50, 52), populated in renderRecents (app.js:121-128). Keep the datalist and chips in sync when recentIds changes (app.js:113).
- The Refresh button (index.html:103) calls request_refresh and shows 'Requested a fresh frame' (app.js:241-244) without waiting for any result.
- No OS detection exists in app-ui. Any platform-specific copy must be introduced deliberately.
