## gotchas
- Viewer teardown is missing. start_viewer_transport (768-961) and begin_viewer (748-752) never call teardown. Only begin_host does (595). So a second Offer arriving while a viewer session exists overwrites SESSION at 953-960 with no stop of the old threads. Those threads, including the keyhook thread and the input thread, keep running. The old thread stop flag is never set.
- Signal race at session start. begin_host sends the offer at 661-667 before SESSION is set at 734-741. start_viewer_transport sends the answer at 789-795 before SESSION is set at 953-960. on_signal drops any non-Offer that arrives while SESSION is None (756-766), so an answer or ICE-like message arriving in that window is lost silently. The comment at 1046-1047 and elsewhere does not mention this race.
- Silent failure paths. begin_host returns with no UI or log beyond tracing::error when bind_and_gather fails (626-632). It also returns silently if api.apply() yields None (659-671), in which case pending is None and no offer is sent. start_viewer_transport logs and returns when bind fails (779-785). If accept_offer fails (786-799), only a warning is logged, and the function still spawns all threads and sets SESSION around a dead Rtc. If SdpOffer parsing fails, nothing is logged. The Driver doc comment at 115-117 says transport death is surfaced to the UI, but these startup failures are not.
- IPv4 socket with IPv6 host candidates. bind_primary_socket returns a 0.0.0.0 wildcard socket if primary_local_ip fails (292). primary_local_ip itself only ever returns IPv4 (298-307, because its probe socket is IPv4). When bound.ip() is unspecified, local_host_candidates (134-155) adds non-link-local IPv6 addresses (142-147) even though the socket is IPv4. Those IPv6 candidates can never be reached through an IPv4 socket. The srflx base lookup (199) is family-matched, but the host-candidate set is not.
- Host candidate must equal the socket local address. The comment at 169-174 says str0m matches received packets to a local candidate by the destination address reported as socket.local_addr(). A wildcard bind would make that 0.0.0.0:port and break ICE. Any port of bind_and_gather must bind to a routable address, and the STUN and TURN bases must also match this address.
- srflx is silently dropped if no host base has the same family (198-206). The code path logs nothing when the base is None, because the if-let at 199 has no else.
- STUN is blocking and sequential. gather_srflx sets an 800 ms read timeout (316) and walks every STUN URL and every resolved address (317-332). stun_query returns None on the first recv error or timeout (360) and reads up to three non-matching datagrams (358-368). begin_host and start_viewer_transport therefore block for up to about 800 ms per STUN address, multiplied by the fallback list (three URLs at 515-519). Its DNS resolution is also blocking. The caller thread is not specified in this range.
- Unrelated datagrams are consumed. stun_query reads from the same socket that ICE will later use, before set_nonblocking(true) at 257. Packets that arrive during gathering are read and discarded if they are not from the STUN server (363).
- TURN turns: scheme is silently ignored. ice_config_from (500) matches only strip_prefix("turn:"). A url beginning with turns: does not match and is dropped without a log. Entries containing transport=tcp are skipped at 497-499. Only UDP TURN is supported. The default port is 3478 when none is given (503-505).
- TURN candidate gets a relayed base equal to the bound socket (241). That is the socket on which allocate() ran (230), so STUN and TURN share one socket. The TURN allocation is only kept if str0m::Candidate::relayed succeeds, and the loop breaks on the first success (249-251).
- Constants: MAX_FPS (458) must equal EncoderConfig::fps_num, because CBR budgets bits per declared frame (455-457). MAX_FPS_INTERVAL is computed with integer division, so it is 33 ms rather than 33.33 ms (459-460). MIN_BITRATE is documented as a hard floor below which 1080p is illegible (443-448). DESIRED_BITRATE (453) is not referenced in lines 1-1060, and MIN_FPS (463) is not referenced in lines 1-1060.
- Initial bitrate and link are both TARGET (674-675). Host Driver comments say the pacer drains against the raw link value and not the floored bitrate (110-113). A port must keep the two separate.
- force_key is a deliberate invariant (104-106). Frames sent before the video channel opens are lost on the wire, so the first deliverable frame must restart the decoder. The Driver doc marks force_key as set both on channel open and on viewer KeyframeRequest. In this range it is initialized to false at 676 and is not set to true anywhere in lines 1-1060.
- Clipboard gating is tied to live permission. clip_on = clipboard_sync && Permission::Control at start (684-686). set_control recomputes clip_on as allow && CLIPBOARD_SETTING (1028-1031). The comment at 678-681 says a view-only peer must not read or write the clipboard. CLIPBOARD_SETTING is updated only at session start (682 and 822), not on settings change, so a mid-session toggle of clipboard_sync is not reflected here.
- Viewer clip_on ignores the peer permission (823). The host applies the gate, not the viewer. Its control AtomicBool is initialized to false (957) and is then unused on the viewer.
- Mouse-move coalescing. The input thread (833-877) paces Move events at 10 ms (840). It sleeps to pace, then drains the queue and keeps the newest Move (853-855). The first non-Move event encountered during the drain is stored as follow and sent after the Move (857, 866-871), and the drain breaks there. Moves queued after that event are processed in the next iteration. Non-Move events that arrive first are not paced. Serialization failure produces empty bytes (864 and 869, unwrap_or_default), and an empty ctl message is sent rather than dropped.
- translate_input drops unknown inputs silently. Buttons that fail protocol::Button::try_from return None (975). Keys with no scancode mapping return None (988). Neither is logged in this range.
- Keyhook events are already DOM codes. The keyhook callback at 933-944 emits InputMsg::KeyDown/KeyUp with the code string directly. Key events from the input sink go through scancode mapping at 988 instead. Two parallel key paths exist and must produce identical codes, since both are used for the same physical keys. The keyhook thread only installs when install() returns true (945-948). When it returns false the thread ends with no log.
- keyhook focus root. set_focus_root receives RENDER_HWND.load() at 929. If the child window was never created, the value is 0 and this is not checked.
- Process-wide statics assume a single session. VIEW_SIZE is reset only by begin_host (597). PASTE_DROPPED is set only at begin_host (683) and never at viewer start. NEGOTIATED_CODEC persists after teardown. Its default of H264 (541) applies if set_negotiated_codec_from_caps is never called (the host's negotiated value is read at 618 with no fallback check).
- Teardown joins threads that may not exit quickly. teardown joins every thread (1043-1045).
