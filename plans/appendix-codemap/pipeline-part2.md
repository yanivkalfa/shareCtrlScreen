# pipeline-part2 (lines 1060-1800: transport_driver — the str0m event loop, channels, bitrate/loss logic, keyframe handling, input forwarding, disconnect)

## summary
pipeline.rs lines 1060-1785 contain transport_driver, the single thread that owns the str0m Rtc, the UDP socket and (optionally) the TURN allocation for one session. It is spawned per session and joined from teardown() (1036-1052). The function is a poll loop: each pass drains the signal, ctl, video, cursor and bulk channels, optionally runs TURN housekeeping, then calls tp.poll_output() once and handles exactly one of Transmit (send via socket or TURN relay), Timeout (drain up to 64 datagrams from the non-blocking socket, or call handle_input(Timeout) and sleep 1 ms when nothing arrived), or Event (mapped via tp.on_event to transport::Inbound). Liveness and keepalive run at the top of each pass: DEAD_AFTER 20 s (1154), application Ping every 2 s (1162), PONG_GRACE 15 s (1164), TROUBLE_AFTER 3 s (1168) with a UI countdown tick every 900 ms (1230). Role-specific behaviour is selected by host_side = frame_rx.is_some() (1130) and inject.is_some() (1446). Host: writes encoded AUs to the RTP media track, injects remote input, receives files, and reports the view size and clipboard. Viewer: reassembles AUs, applies a keyframe gate, and sends files. Pure logic (channel handling, liveness, gating, bitrate policy, fit_within at 1791-1803) is separated from Windows calls, which are confined to a small set of named seams listed in platform_deps.

Shutdown has three paths. (a) stop flag observed at loop top. (b) Inbound::Disconnected, Ctl Bye, transport poll error, or a dead watchdog, each calling notify_dead, which resets Role to Idle exactly once and emits Toast, RoleChanged(Idle), and hides the video surface. After the loop, if the role is still active, stop is set (1777-1779). (c) Post-loop Bye pump (1752-1773): if stop is set and ctl is open and connected, the Bye is sent and up to 250 ms of tp.poll_output() Transmits are flushed. Finally, host releases all injected input (1782-1784). Session statics are defined at 25-45 (RENDER_HWND, SESSION, CURSOR, CLIPBOARD_SETTING, PASTE_DROPPED, VIEW_SIZE). Public functions adjacent to the range are create_video_window (50), set_video_visible (1009), set_control (1023) and teardown (1036).

## gotchas
- Comment invariant (1151-1153): DEAD_AFTER (20 s) must stay above PONG_GRACE (15 s) so the app-level keepalive, which can explain itself to the user, fires first. Keep the relation when porting or retuning.
- Comment invariant (1158-1161): UDP liveness (last_rx, 1386) counts STUN/TURN keepalives, so UDP can look healthy while the session is wedged. That is why the app-level Ping/Pong exists. Pong grace starts only when the ctl channel opens (1206, 1456), so channel setup time is not charged against it.
- On link trouble the viewer hides the native surface (1225-1227) so the user does not stare at a frozen frame. On recovery it shows it again and sends a KeyframeRequest over ctl (1239-1243). The host only emits LinkTrouble/LinkRestored and never toggles visibility.
- Frames sent before the track or channel is open are lost, so the host sets force_key on Connected (1438-1443). The comment says the first deliverable frame must be an IDR. Keyframe requests also come in via RTCP PLI (1515-1518) and via the ctl KeyframeRequest (1565-1570). The host rate limit is claimed to live in host_media_loop (1513-1514, not verified here).
- CORRECTNESS GATE (1479-1503): a non-contiguous non-keyframe sets drop_till_key. Every delta is then dropped (1489-1502) until a keyframe arrives, and a keyframe with contiguous=false still passes. PLI goes out at most once per 500 ms, on both native rtc.request_keyframe() and the ctl KeyframeRequest. last_pli is initialised 5 s in the past (1181) so the first request is immediate.
- Bitrate: the BWE estimate goes to two places. The encoder target is clamped to [2.5 Mbps, 8 Mbps] with a 15% hysteresis (1533-1542). The source pacer uses the raw link value floored at 100 kbps (1525), so the encoder is never asked for less than MIN_BITRATE even when the link cannot carry it. The MIN_BITRATE comment (1443-1448, 1527-1531) says the floor is deliberate because text is illegible below about 2.5 Mbps.
- fit_within (1791-1803) rounds to even dimensions because H.264 4:2:0 chroma needs it. The comment says the Windows Media Foundation MFTs reject odd sizes. The even rounding is generic to H.264, and the no-upscale and aspect-preserve rules are also generic.
- Control revocation (1277-1285): when the gate flips true to false, held keys and buttons are released via inj.release_all(). The edge detector was_control starts true (1112). Exit also releases all input (1780-1784). Any port must release held input on both paths.
- Clipboard gate (1587-1596): the host requires the live control gate, and the viewer has no gate (inject None means allowed=true). Text longer than MAX_TEXT_BYTES is silently dropped. Clipboard exchange is tied to control via clip_on (1028-1031), so revoking control also stops clipboard exchange.
- Bulk gate (1626-1634): inbound file bytes are accepted only when the host's control gate is open. On a viewer, inject is None so every inbound bulk frame is dropped. If control is revoked mid-transfer, the partial Incoming is removed with take() on the next Bulk frame (1629-1632), not on revocation, and abort() is not called there. Whether dropping Incoming cleans up the partial file depends on transfer.rs, which was not checked.
- Bulk framing: a new Begin supersedes any in-flight transfer and aborts it first (1642-1644). The transfer has no id, so overlapping transfers would interleave, per the comment at 1807-1809. Malformed BulkFrame::decode results are ignored (1635-1637).
- Viewer file push backpressure (1337-1353): bytes are only queued while tp.bulk_buffered() < 256 KiB (BULK_QUEUE_LIMIT, 1343). This keeps video from being starved by SCTP.
- ctl_backlog (1146, 1312, 1457-1459) is an unbounded Vec<Vec<u8>> that buffers control messages until the ctl channel opens. Cursor messages before open are dropped, not buffered (1330-1334). Control state is buffered on purpose because losing the initial Perm desyncs the session.
- Frame drain (1315-1327) has no per-pass cap, while the bulk drain is capped by backlog size. The viewer video_tx (1504-1506) is an unbounded std mpsc. A slow decode thread would grow memory without backpressure.
- Socket drain (1380-1425): at most 64 datagrams per Timeout pass (comment 1375-1379 explains that one-per-cycle could not keep up with about 300 pkt/s plus NACK and TWCC). Any recv Err ends the drain (1423), including Windows WSAECONNRESET. Transmit and Event outputs do not sleep, so the loop is a busy poll while str0m produces output.
- Input and control share one ctl channel and one JSON format. ControlMsg is tried first (1549). Any variant the host does not handle (for example Perm, Cursor) falls through to InputMsg parsing and is silently ignored. A ControlMsg variant that happens to parse as InputMsg would be misrouted. The dispatch order is therefore load-bearing.
- Host input path calls desktop.follow() before every dispatch (1610-1612), with the error ignored. This is per-event cost, not per-session.
- Teardown Bye pump (1752-1773): it pumps at most 250 ms and breaks on the first non-Transmit output (1770), so the Bye is not guaranteed to reach the wire if str0m yields an Event or Timeout first. The Bye is sent only when stop is set and ctl is open and connected. A dead-transport exit does not send it (notify_dead has already run).
- notify_dead (1088-1108) checks role and then sets Idle in two separate lock acquisitions (1092, 1094). This is not atomic, but it is safe only while no other thread changes role concurrently. It is run exactly once per exit path by convention (break after call).
- notify_dead also hides the native surface (1100), clears input and file-drop sinks (1101-1102), then emits Toast and RoleChanged(Idle). Order matters: the surface must go before the UI learns the session is dead, because it sits on top of the web UI.
- serialize (1054-1056) uses unwrap_or_default: a serialization failure silently sends an empty Vec on the ctl channel.
- Stats (1247-1276): one INFO line per 5 s per side. Host logs fps, idr, pli-in, applied kbps (from bitrate) and bwe kbps (last_est). Viewer logs fps (stat_sent, which counts received frames including dropped ones), gaps and dropped. stat_sent is shared between the roles with different meanings.
- Loop termination order (1196-1202): stop is checked at the top of each pass only, and dead-watchdog checks come before ping. After a break, the path differs by cause (see the teardown Bye pump), so keep that ordering when porting.
- Comment at 1438 says the viewer's decoder has no reference yet, so the first IDR is needed. The comment at 1119-1120 says the socket is bound and its host candidates are registered before the SDP is generated, which is a hard ordering requirement for the offer/answer and sits in bind_and_gather (165-259, not in range).
