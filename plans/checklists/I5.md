# I5 — Cross-codec matrix: tester checklist

What this verifies: every encoder in the project produces a stream every
decoder reproduces bit-exactly (FFmpeg's per-frame hashes), and every
encoder's output has the shape the viewers rely on (Annex-B, IDR first,
parameter sets on every IDR, no reordering, forced keyframes honoured).
Golden files and the procedure: `native/testdata/golden/README.md`.
Code: `native/crates/codec-goldens`.

Verified on machine A (GTX 1080 Ti) when the task was built:

| Decoder | nvenc-h264 | nvenc-hevc | openh264-cb | x264-high | size change on one decoder |
|---|---|---|---|---|---|
| Media Foundation (Microsoft software H.264 decoder; no hardware decoder MFT enumerates on NVIDIA) | PASS | SKIP (HEVC not advertised without a hardware MFT) | PASS | PASS | PASS |
| OpenH264 2.6.0 (Windows and WSL2) | PASS | SKIP (H.264 only) | PASS | PASS | PASS |
| NVDEC (WSL2) | PASS | PASS | PASS | PASS | PASS |
| VA-API | §3 | — | §3 | §3 | §3 |
| VideoToolbox | §2 (task T2's test) | §2 | §2 | §2 | §2 |

Encoder shape: NVENC H.264/HEVC PASS, OpenH264 PASS, Media Foundation
(software fallback, see §1) H.264/HEVC PASS. VideoToolbox (§2) and VA-API
(§3) are device-pending.

## 1. Media Foundation hardware goldens (Windows with a working hardware MFT)

**Device-pending.** On machine A the NVIDIA H.264 and HEVC encoder MFTs
fail to open (the owner's known quirk of that machine; log line `hardware
H264 encoder failed (windows: Catastrophic failure (0x8000FFFF)) — trying
the software encoder`). Media Foundation then uses Microsoft's software
encoder, so no `mf-*` golden is written there: a golden named after the
hardware MFT must come from it.

On a Windows machine whose hardware H.264/HEVC MFT opens (machine B or any
other; log line `encoder ready: H264 (hardware, …)`), run the ignored
regenerate test, then the FFmpeg hash step in WSL/Linux, and commit the
three files of each stream once:

```powershell
cd native
cargo test -p platform-windows -- --ignored regenerate_media_foundation_goldens --nocapture
```

Expected: `wrote mf-h264-640x360.h264: 30 access units`, `mf-h264-480x270`,
and `mf-hevc-640x360` where a hardware HEVC MFT exists. The test fails, and
writes nothing for that stream, with "fell back to the software encoder"
if the hardware MFT is not used. Then, in WSL2 (FFmpeg installed):

```bash
cargo test -p codec-goldens -- --ignored write_missing_ffmpeg_hashes --nocapture
cargo test --workspace   # every decoder now checks the new streams
```

Commit the `.h264`/`.hevc`, `.aus` and `.sha256` once, and add a row for
each to the golden README.

**NVIDIA MFT HEVC check:** the line `Media Foundation Hevc (hardware)` in
`cargo test -p platform-windows golden_tests -- --nocapture` must appear
once the hardware MFT works. On machine A it reads `(software)`.

## 2. VideoToolbox goldens and decoder row (a Mac, Apple silicon)

```bash
cd native
cargo test -p platform-macos --test vt_goldens -- --ignored --nocapture
```

Expected: `videotoolbox_output_has_the_engine_shape` prints a `Shape` for
H264 (and Hevc), and `regenerate_videotoolbox_goldens` prints `wrote
vt-h264-640x360.h264: 30 access units`, `vt-h264-480x270`, and
`vt-hevc-640x360`. Copy the six new files (`.h264`/`.hevc` + `.aus`) to a
machine with FFmpeg and run step 2 of the README (`write_missing_ffmpeg_hashes`).
Then, on the Mac, run the VideoToolbox decoder row against every golden:

```bash
cargo test -p platform-macos --lib decode::tests::golden_streams_match_ffmpegs_frame_hashes -- --ignored --nocapture
```

Expected: every stream `… frames match FFmpeg`, and the resolution-change
line. Commit the new goldens; then every other decoder (CI) checks them.

## 3. VA-API on machine B (Intel/AMD, Ubuntu 24.04 live USB)

After plans/checklists/L4.md §0:

```bash
cd native
cargo test -p platform-linux --all-features -- --ignored --nocapture \
  vaapi_decodes_the_golden_streams vaapi_output_has_the_engine_shape
```

Expected: `matrix: vaapi × <stream>: PASS` for every H.264 golden plus the
resolution-change line, and `VA-API H264: Shape { … keyframes: [0, 15] … }`.
Paste the output into the report.

## 4. CI follow-up

`native-ci.yml` requires only `openh264` (`SCT_CODEC_TESTS_REQUIRED`) on
windows-latest and ubuntu-22.04. The Media Foundation rows run on the
Windows runner but skip if Microsoft's H.264 MFTs are missing there, which
no run has checked yet. After the first pushed run, read the Windows Test
log: if it shows `matrix: media-foundation × nvenc-h264-main-640x360: PASS`,
change the Windows entry to `openh264,media-foundation`.
