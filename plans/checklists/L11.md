# L11 — Linux packages: tester checklist

Needs: the `sharectrl-linux` artifact from the `linux-build` workflow (Actions, run on
`port/multi-os`), and fresh VMs: Ubuntu 22.04, Ubuntu 24.04, Fedora 40 (live ISO or
installed, GNOME). Record result and `vainfo` output per VM.

## Per package

| VM | Package | Install command |
|---|---|---|
| Ubuntu 22.04 | `.deb` | `sudo apt install ./ShareCtrlScreen_*_amd64.deb` |
| Ubuntu 24.04 | `.deb` | same |
| Fedora 40 | `.rpm` | `sudo dnf install ./ShareCtrlScreen-*.x86_64.rpm` |
| All three | `.AppImage` | `chmod +x *.AppImage && ./ShareCtrlScreen_*.AppImage` (install `libfuse2` / `fuse-libs` first; on Ubuntu 24.04 it is `libfuse2t64`) |

For each:

1. [ ] Install completes with no unmet dependencies (deb/rpm: `apt`/`dnf` pulled only
   distribution packages; nothing was forced).
2. [ ] `ShareCtrlScreen` appears in the application menu with its icon, under Internet /
   Network; searching "remote desktop" finds it.
3. [ ] The window opens; the UI renders (no blank/white window). On a blank window under
   Wayland, retry with `WEBKIT_DISABLE_DMABUF_RENDERER=1 sharectrl` and note it.
4. [ ] `~/.local/state/sharectrl/app.log` exists and has startup lines.
5. [ ] deb: `dpkg -s share-ctrl-screen`
   lists `Depends` with webkit2gtk-4.1, gtk-3, pipewire-0.3, xkbcommon and `Recommends`
   with libva2. rpm: `rpm -qR <pkg>` lists the equivalents.
6. [ ] Uninstall (`apt remove` / `dnf remove`) removes the binary, menu entry and icons;
   `~/.config/sharectrl` is kept.
7. [ ] On one extra VM install with weak dependencies off (`sudo apt install
   --no-install-recommends ./*.deb` / `sudo dnf install --setopt=install_weak_deps=False
   ./*.rpm`) and confirm the app still starts (libva is dlopen'd; software encode is used).

## VA-API diagnostics (`vainfo`)

```sh
sudo apt install vainfo        # Fedora: sudo dnf install libva-utils
vainfo
```

* Healthy: lists `VAProfileH264Main` / `VAProfileH264High` with `VAEntrypointEncSlice`
  or `VAEntrypointEncSliceLP`.
* `libva error: ... failed to initialize display` / `vaInitialize failed`: no render node
  or driver. Check `ls -l /dev/dri/renderD*` and that your user is in the `render` group.
* Profiles listed but no `EncSlice` entry: the driver decodes only. Intel: install
  `intel-media-va-driver-non-free`. Fedora: `sudo dnf install mesa-va-drivers-freeworld`
  from RPM Fusion (Fedora's own Mesa build omits H.264).
* Force a driver: `LIBVA_DRIVER_NAME=iHD vainfo` (Intel), `radeonsi` (AMD).
* NVIDIA has no VA-API encode; the app uses NVENC or software there.

## Enabling uinput (remote control without the portal)

1. [ ] Settings, "Enable uinput access" (when the UI lands, task D5/L12). Until then:
   follow the manual `sudo` block in `native/README.md`, "Linux install".
2. [ ] Enter your password in the polkit dialog; cancelling shows a clear message.
3. [ ] `cat /etc/udev/rules.d/70-sharectrl-uinput.rules` shows the rule;
   `id -nG` lists `input` after you log out and in.
4. [ ] `ls -l /dev/uinput` shows `crw-rw---- root input`.
5. [ ] Revoke: delete the rule and modules-load file, `sudo gpasswd -d "$USER" input`.
