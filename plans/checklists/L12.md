# L12 — Linux permissions preflight (real desktop)

Needs a GNOME (>= 45) or KDE Plasma 6 Wayland session, plus one wlroots/Hyprland session if
available. Build: `cargo test -p platform-linux -- --ignored` runs the automated half.

Token file: `${XDG_STATE_HOME:-~/.local/state}/sharectrl/portal.token` (mode 0600; line 1 = token,
line 2 = `input` when the token also restores remote control).

## GNOME / KDE (Wayland)
1. Fresh state: delete the token file. `permissions()` reports screen capture and input injection
   `NotDetermined`; a VA-API note is present; no dialog appeared.
2. Trigger `request_permission(ScreenCapture)`. One portal dialog (choose a monitor). Afterwards the
   token file exists, has mode 0600 and no `input` line; `permissions()` => screen `Granted`,
   input `NotDetermined`.
3. Delete the token. Trigger `request_permission(InputInjection)`. One combined dialog ("share screen
   and allow remote control"). Token file has the `input` line; `permissions()` => both `Granted`.
4. Trigger `request_permission(InputInjection)` again: no dialog (token renewed silently) on GNOME;
   on KDE a dialog may reappear (known restore bugs) — record which.
5. Click the request twice quickly: only one dialog.
6. Dismiss the dialog with Cancel: no token written, state unchanged, a log line "dismissed by the user".
7. Revoke in system settings (GNOME: Settings > Privacy > Screen Sharing; KDE: Permissions) and
   re-probe: record whether `Granted` is still reported (the token is only invalidated when used —
   expected, L1 handles the failed restore).

## Hyprland / wlroots without RemoteDesktop
8. `permissions()` => input `Denied` with the note "this desktop has no remote-control portal; enable
   the uinput fallback in Settings". After the udev rule from L11 is installed and the user is in the
   `input` group (re-login), input becomes `Granted` with the `/dev/uinput` note.

## X11
9. Both screen capture and input `NotApplicable`; the X11 note is shown.

## Probe speed
10. `permissions()` returns in well under a second on a healthy desktop; with `xdg-desktop-portal`
    stopped it returns within 3 s with screen `Denied`.
