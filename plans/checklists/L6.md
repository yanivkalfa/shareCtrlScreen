# L6 — Linux input injection (real desktops)

Automated half: `cargo test -p platform-linux input::` (Xvfb, uinput, in-process EIS,
headless sway; each prints a `SKIP:`/`skipping:` line when its peer is missing, and
the `x11-tests` job of `.github/workflows/native-ci.yml` runs the `input::tests::xtest` and
`input::tests::uinput` filters with the uinput access set up in its own step, so uinput runs
without root; the libei test is T4's EIS peer and the wlroots test needs sway, left to T4; and
`SCT_X11_TESTS_REQUIRED=1 SCT_LINUX_INPUT_TESTS_REQUIRED=1` make those skips failures) and `cargo test -p platform-linux -- --ignored
portal_libei` inside a GNOME/KDE session. The app log (`~/.local/state/sharectrl/app.log`) names the
backend at session start: `remote control uses …`.

For every desktop below, from a second machine (the viewer) with control granted:
* **A. Pointer:** move to all four corners of the shared monitor; the host cursor reaches each
  corner and never jumps to a neighbouring monitor. With two host monitors, share the
  non-primary one and repeat.
* **B. Buttons:** left click focuses/activates, right click opens a context menu, middle click
  pastes the primary selection in a terminal; drag a window by its title bar.
* **C. Wheel:** one notch scrolls one step up/down in a browser; horizontal scroll (Shift+wheel or
  a tilt wheel) scrolls sideways.
* **D. Keys:** type `Hello, World! 123` in a text editor; Ctrl+A/C/V work; hold a letter for 2 s —
  it repeats at the *host's* rate, not twice as fast; Caps Lock toggles and its LED/indicator
  follows; host layout German: the key right of `T` types `z`. wlroots (Sway/Hyprland): the
  virtual keyboard starts with NumLock off whatever the host's keyboard shows (its lock state
  is not inherited) — press NumLock once from the viewer before testing the keypad; record it.
* **E. Release:** hold Shift and the left button from the viewer, then revoke control (view-only)
  — the host has no stuck Shift or button. Repeat by closing the viewer window.
* **F. File drop:** drop a file onto a host window: X11 — the window under the drop point comes to
  the front and the file is pasted; Wayland — the file stays on the clipboard with a toast.

## GNOME 46+ (Wayland, portal + libei)
1. Fresh: delete `~/.local/state/sharectrl/portal.token`. Start hosting; on connect exactly one
   dialog ("share screen and allow remote control") appears — never a second screen-only one;
   accept. Log: `the RemoteDesktop portal (libei)` and `portal: shared session node …`.
   With two monitors, pick the second in the dialog: the viewer's pointer lands on the second
   monitor (A), not on the first.
2. Run A–F.
3. Disconnect, reconnect: no dialog (token restored). The token file changed (single-use).
4. Click the orange "screen shared" indicator → Stop: input stops with a log line `the desktop
   ended remote control` or `closed the remote-control connection`; the app is not stuck.
5. Decline the dialog on a fresh token: the session stays view-only, the log says "declined on this
   computer".

## KDE Plasma 6 (Wayland, portal + libei)
6. As 1–5. Record whether the restore in step 3 needed a dialog (known KDE restore bugs).

## Sway (wlroots)
7. Log: `the wlroots virtual pointer and keyboard`; no dialog at all. Run A–E.
8. `swaymsg -t get_inputs` lists an extra pointer and keyboard while a session is active and not
   after it ends.
9. With `input type:keyboard xkb_layout de` in the sway config, check the German item of D.

## X11 (Ubuntu 22.04 Xorg session in a VM)
10. Log: `XTest (X11)`. Run A–F. In F the window under the drop point is raised and focused
    (GNOME on Xorg honours `_NET_ACTIVE_WINDOW` from a pager source).
11. Two monitors (VM with two displays): share the second; A lands on it.

## uinput (Ubuntu 24.04 live USB, any session)
12. Before setup, on a desktop without portal or wlroots (e.g. Weston): connecting gives the toast
    "Remote control is unavailable …" naming "Enable uinput access".
13. Settings → Enable uinput access (polkit dialog). Before re-login the refusal says "log out and
    back in"; after re-login the log says `uinput virtual devices` and A–E work.
14. `sudo rmmod uinput` (no session active): the refusal says the module is not loaded and
    mentions `modprobe uinput`.
15. GNOME with uinput forced (portal stopped: `systemctl --user stop xdg-desktop-portal`): record
    whether the absolute pointer covers the whole layout on a two-monitor setup (A).
