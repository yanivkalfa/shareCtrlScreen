# M1 — ScreenCaptureKit capture: Mac tester checklist

What this verifies: the macOS screen capture backend (`native/crates/platform-macos`,
`SckCapture`). It cannot run in CI (TCC needs a real logged-in user), so these steps are the
only proof it works. Takes about 25 minutes.

Report back: the macOS version, the Mac model (Intel or Apple Silicon), the display setup
(built-in only / + external, resolutions, "looks like" scaling), and **the full terminal
output of every step** (copy-paste or a text file).

## 0. Setup (once)

1. macOS 13 Ventura or newer, logged in at the desktop (not over SSH — a GUI session is
   required).
2. Xcode command-line tools (`xcode-select --install`) and Rust (`https://rustup.rs`).
3. Get the branch: `git clone … && cd shareCtrlScreen/native && git checkout task/M1`
   (or the branch the orchestrator names).
4. Build the tests once: `cargo test -p platform-macos --no-run`.

## 1. Grant Screen Recording

1. In Terminal: `cargo test -p platform-macos --test sck_smoke -- --ignored --nocapture --test-threads=1 lists_displays`
2. Expected: a list of your displays, each with an id like `cg:610-a050-0`, `primary: true`
   on exactly one, `scale: 2.0` on Retina panels. The test passes.
3. Run step 4.1 below once. macOS shows **"Terminal would like to record this computer's
   screen"**. Click **Open System Settings**, turn **Terminal** on under
   *Privacy & Security → Screen & System Audio Recording*, then **quit and reopen Terminal**
   (the grant only applies to a fresh process).
   * If you clicked "Don't Allow" by mistake: `tccutil reset ScreenCapture com.apple.Terminal`
     and run again.
4. Run the `lists_displays` test again: the `permissions:` line must now say
   `screen_capture: Granted`.

## 2. Frame rate, CPU, idle screen  (acceptance)

1. Open a 60 fps video full screen (e.g. a YouTube 4K60 clip) or keep dragging a window in
   circles. Run:
   `cargo test --release -p platform-macos --test sck_smoke -- --ignored --nocapture --test-threads=1 captures_busy_then_idle_screen`
2. **PHASE 1** (10 s, keep it moving). The log must show
   `sck: capturing display … at WxH (native WxH), 420v, ≤60 fps` where W×H is the panel's
   **pixel** size (e.g. 3840x2160 for a 4K display, 2880x1864 / 3024x1964 on MacBooks).
   Then a line `=> NN.N fps, process CPU N.NN %`.
   * Expected: **55–60 fps** on a 60 Hz display with full-screen motion (a 4K display
     included); **CPU < 1 %** (this is our process only — WindowServer/replayd do the
     scaling and are not counted).
   * `superseded` in the closing `sck: stream closed` line should be small (< 5 % of
     delivered) — it counts frames the test was too slow to take.
3. **PHASE 2** (10 s, hands off, stop the video). Expected: `idle:` shows a large `idle` count
   and `frames` near 0 — a static screen yields `Ok(None)`. Move the mouse in the last
   seconds: `pointer_only` and `cursor_updates` go up while `frames` stays ~0 (the pointer
   is not drawn into the video). `shapes` ≥ 1 (the arrow's bitmap was sent once).
4. Test passes.

## 3. Rebuild and resize

`cargo test -p platform-macos --test sck_smoke -- --ignored --nocapture --test-threads=1 reinit_and_resize`

Expected: `sck: stream rebuilt at WxH after 0 failed attempt(s)`, then
`sck: capture size WxH → 1280x720` (or the 16:10 equivalent, e.g. 1152x720), then back to
native. Test passes. No `dropping … frame` warnings after the first second of each phase.

## 4. Display sleep / wake, lock screen, permission revocation  (acceptance)

`SCK_SOAK_SECS=600 cargo test -p platform-macos --test sck_smoke -- --ignored --nocapture --test-threads=1 soak`

It prints one line every 5 s. While it runs, do each of these and note the time:

1. **Display sleep**: Apple menu → Lock Screen is *not* this; use `pmset displaysleepnow`
   in a second Terminal, wait 30 s, wake with a key press.
   * Expected: either frames simply stop and resume, or `sck: stream stopped … → Lost`,
     `LOST → reinit`, possibly some `reinit failed` lines while the display is off, then
     `sck: stream rebuilt …` within ~5 s of waking. Frames resume. **It must not hang or
     exit.**
2. **Lock screen with you logged in** (Ctrl+Cmd+Q), wait 20 s, unlock.
   * Report exactly what the log shows while locked (frames? idle? stopped?). Decision #8
     needs the lock screen visible to a remote user; we need to know what ScreenCaptureKit
     delivers there.
3. **Change resolution** (System Settings → Displays → a different "looks like" size) and
   back. Expected: `Lost` + rebuild, and the `(W, H)` printed on each line follows the new
   pixel size.
4. **Unplug / replug an external display** (if you have one) — same as 3.
5. **Revoke the permission last**: System Settings → Screen & System Audio Recording → turn
   Terminal **off** (macOS may ask to quit Terminal — choose **Later**).
   * Expected: `sck: stream stopped … → PermissionDenied` (or `LOST` followed by a failing
     reinit) and then `PERMISSION DENIED (expected after revoking Screen Recording)`; the
     test ends. In the app this error is what triggers the "permission needed" toast.
   * Turn the permission back on afterwards.

## 5. Things to send back regardless of pass/fail

* All terminal output from steps 1–4.
* `log show --last 15m --predicate 'process == "replayd"' > replayd.txt` if anything in
  step 4 hung or never recovered.
* On macOS 15+: whether the monthly "…is requesting to bypass the system private window
  picker" prompt appeared at any point.
