# M10 — macOS bundle, signing, first run (tester checklist)

Needs: a Mac on macOS 13+ (Apple Silicon or Intel), the DMG from the `Build macOS DMG`
workflow run (Actions → the run → Artifacts → `ShareCtrlScreen-macos-universal`, unzip once
to get the `.dmg`), and a second DMG from a later run for the update test.

## A. First launch (fresh download)

1. Download the artifact in a browser (so it is quarantined like a real download), open the DMG,
   drag `ShareCtrlScreen` to `Applications`.
2. Launch it. Expect the dialog *"Apple could not verify "ShareCtrlScreen" is free of malware…"*
   with buttons **Done** / **Move to Trash**. Click **Done**.
   - If you see *"ShareCtrlScreen is damaged and can't be opened"* instead, see section D.
3. System Settings → Privacy & Security → scroll to the *Security* section → *"ShareCtrlScreen"
   was blocked…* → **Open Anyway** → enter your password → **Open Anyway** once more.
   (macOS 15 Sequoia removed Control-click → Open, so the right-click route does nothing.)
4. The app window opens. Pass: it does, with the ShareCtrlScreen icon in the Dock (blurry is
   expected: the source art is 32 px).
5. Alternative to 2–3, for comparison: `xattr -dr com.apple.quarantine /Applications/ShareCtrlScreen.app`
   and launch again; the dialog must not appear.

## B. The signature is the right kind

In Terminal:

```sh
codesign -dr - /Applications/ShareCtrlScreen.app
```

Pass: the line starts `designated => identifier "dev.netameta.sharectrl" and certificate leaf = H"…"`.
Fail: it says `cdhash H"…"` — that is an ad-hoc build (the repository secrets were missing when it was
built); permissions will not survive an update. Write the `H"…"` value down.

```sh
codesign --verify --strict --verbose=2 /Applications/ShareCtrlScreen.app
lipo -archs /Applications/ShareCtrlScreen.app/Contents/MacOS/sharectrl
```

Pass: `valid on disk` / `satisfies its Designated Requirement`, and `x86_64 arm64`.

## C. The signature survives an update

1. In the first build, grant **Screen & System Audio Recording** (System Settings → Privacy &
   Security) and **Accessibility** to ShareCtrlScreen.
2. Quit the app. Install the second DMG over it: drag to `Applications`, **Replace**. Same path.
3. Repeat A3 if macOS blocks the new build again (a new download is a new quarantine; this is expected).
4. Run `codesign -dr - …` again. Pass: the `certificate leaf = H"…"` value is **identical** to B.
5. Open the two Privacy & Security panes. Pass: ShareCtrlScreen is still listed and still switched
   on, and you were not asked to grant anything again.
   Fail: the `H"…"` differs (the certificate was regenerated — everyone must re-grant, see
   `plans/01-MACOS-FINDINGS.md` §8) or the toggles are off (report the `codesign -dr -` output of both builds).

To reset for a clean retest: `tccutil reset ScreenCapture dev.netameta.sharectrl` and
`tccutil reset Accessibility dev.netameta.sharectrl`.

## D. What "damaged" means

macOS prints *"is damaged and can't be opened. You should move it to the Trash"* when a
quarantined bundle fails signature validation: the signature is missing, or files inside the app
changed after signing (re-zipped with a tool that dropped metadata, edited, partly copied). It is not
the "Apple could not verify" case. Steps: delete the app, re-download the DMG, copy it again with
Finder. If it persists, report `codesign --verify --strict --verbose=4 /Applications/ShareCtrlScreen.app`.
`xattr -dr com.apple.quarantine …` only helps when the signature is valid.

## E. Monthly prompt (Sequoia)

macOS 15+ asks roughly monthly *"…is requesting to bypass the system private window picker"*
for screen capture. This is OS behaviour, cannot be disabled by the app; choose **Allow**.

## Regenerating the icon

`native/app/icons/icon.icns` is produced from `icon.png` with
`cd native && cargo tauri icon app/icons/icon.png --output <tmp dir>` and copying `icon.icns` out
(the command also writes PNG/ICO sets the repository does not use). Replace `icon.png` with a
1024×1024 master first and the icon becomes sharp.
