# M13 — macOS toolbar drawer appears on a top-edge hover: tester checklist

What this proves: on the macOS viewer, pushing the pointer to the TOP edge of the remote
screen slides down the web toolbar (the `.view-bar` with **End Session / Disconnect**),
the buttons are clickable in that strip, and moving back down into the picture hides it
and restores the video exactly. Before M13 the native reveal fired (app.log showed it) but
the strip opened at the wrong visual edge, so the drawer stayed hidden under the video.

None of this can run on a CI runner (needs a GUI session, a real `WKWebView` and a live
session); the reveal state machine itself is covered by
`crates/surface-wgpu/src/reveal.rs` tests on every OS.

## Before you start

* **Mac:** macOS 13 or later. Note the model, macOS version, and whether the display is
  Retina (2×) or not — the strip height differs (40 pt = 80 px on Retina).
* **Build:** a CI-built DMG from `port/multi-os` (or `task/M13` merged) containing M4
  (video view) and a decoder (M3 or D2). Install as in the M4 checklist.
* **Host:** any host (a Linux or Windows PC) sharing its screen, so the viewer shows a
  full remote picture that covers the whole window including the toolbar.
* **Log:** `tail -f ~/Library/Logs/ShareCtrlScreen/app.log` in Terminal. The reveal lines
  (`toolbar reveal: Reveal …` / `Hide …` with the view and layer frames, and the one-time
  `video view: pointer events arrive …`) are kept from M12 — read them for each step.

## 1. The drawer comes down on a top-edge hover (windowed)

1. Connect and let the remote picture fill the window (not full screen).
2. Move the pointer slowly up to the very TOP edge of the picture.
   Expected: the web toolbar slides down at the VISUAL TOP of the window; **End Session**
   and **Disconnect** are visible. Log: a `toolbar reveal: Reveal …` line.
   Before M13 the log line appeared but no bar showed — that is the bug; it must now show.
3. Move the pointer back down into the picture (well below the bar).
   Expected: the toolbar hides and the video fills the window again with no gap or black
   strip anywhere. Log: a `toolbar reveal: Hide …` line restoring the full height.
4. Hover the top edge again and **click End Session** while it is down.
   Expected: the session ends (the button worked — the strip is hit-testable, not just
   painted).

## 2. The strip is at the TOP, not the bottom

1. Reveal the bar (step 1.2) and look at the BOTTOM edge of the window.
   Expected: no empty/black strip at the bottom; the only uncovered strip is the toolbar
   at the top. (The old bug opened a useless strip at the bottom and left the toolbar
   covered.)
2. **If the bar is STILL hidden here**, read the `toolbar reveal:` / layer-sync log lines:
   if the parent layer's geometry-flip EQUALS the parent view's flip (the flips agree),
   the M13 axis fix is a no-op and the cause is NOT the axis — report it as a z-order
   problem (the video view/layer not top-most in the strip) or the `WKWebView` toolbar not
   filling the top 40 px, so the next round looks there instead of at the axis again.

## 3. Full screen

1. Enter full screen (green button or Ctrl+Cmd+F) and let the picture fill the screen.
2. Move the pointer to the very top so the macOS menu bar / title bar slides down.
   Expected: the toolbar still reveals and is reachable below that system overlay; moving
   down hides it. Log: the `system cover …px` value on the reveal line is non-zero.

## 4. The extreme-flick no longer toggles spuriously

1. Flick the pointer quickly up and out past the top edge, then well away from the top.
   Expected: the bar reveals on a genuine top-edge approach but does NOT flip on/off when
   the pointer is nowhere near the top. In the log you should no longer see `Reveal` lines
   at absurd positions (e.g. `at y=-470px` / `y=-1025px`) toggling the bar; a top exit far
   above the edge is now ignored.

## 5. Scale change (optional, if you have a second display)

1. Drag the window between a Retina and a non-Retina display while the bar is hidden, then
   reveal it on each. Expected: the strip height tracks the display (80 px on Retina, 40 px
   otherwise) and the toolbar still shows at the top on both.

For each step write **pass / fail**; for a fail add a screenshot and the `toolbar reveal:`
log lines around it (they print both the view frame and the layer frame plus the parent
layer's geometry-flip, which tells whether the layer gap opened at the right edge).
