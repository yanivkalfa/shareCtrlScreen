# M15 — native menu on macOS + Linux, no top-edge drawer there, Mac cursor leak fixed: tester checklist

What this proves, on **macOS and Linux only** (Windows is deliberately unchanged):

1. A **native menu** appears — on macOS in the system menu bar, on Linux in the app window's menu
   bar — with a **"Session"** menu holding exactly three items: **Settings**, **Disconnect / End
   Session**, **Check for updates**. Each does the same thing as the matching on-screen button.
2. The old **top-edge hover drawer is gone** on macOS and Linux: pushing the pointer to the very top
   of the video no longer shrinks the picture to reveal a web toolbar. The web toolbar stays hidden
   (its buttons now live in the menu).
3. The macOS **OS cursor no longer gets stuck hidden** out on the desktop. While you control and the
   pointer is over the video, the Mac arrow is hidden (only the drawn remote cursor shows); the
   instant the pointer leaves the video / the window, the normal Mac arrow returns.

Why the cursor bug happened: D10 hid the OS cursor app-wide with `NSCursor.hide()` and relied on
`mouseExited` (plus focus-loss) to `unhide`. `mouseExited` does not fire reliably when the pointer
leaves the **whole window**, so the arrow stayed hidden on the Mac desktop until the app lost focus.
M15 replaces that with a **rect-scoped** cursor: a transparent `NSCursor` is set over the video's
rectangle via `resetCursorRects`/`addCursorRect:` only while controlling. AppKit shows it only while
the pointer is inside that rectangle and the window is key, and restores the normal cursor
everywhere else — so it can never leak.

This is a GUI + real-session change; it cannot run on a CI runner. What the build lane **does**
prove on every push: the whole workspace compiles and is clippy-clean (`-D warnings`) on Windows and
WSL **and** type-checks + clippy-checks for `aarch64-apple-darwin` (`platform-macos`), `cargo build
-p app` links, `cargo test --workspace` passes, and the engine loopback runs ×3 with `test-hooks`.
The menu, the removed drawer and the cursor behaviour are **device-only** — this checklist.

## Before you start

* Two machines (LAN is fine). A **macOS** viewer build and a **Linux** viewer build (test each you
  can: Linux X11 and Linux Wayland). Any host build on the other machine.
* Also keep a **Windows** build handy for step 5 (the regression check: Windows must be unchanged).
* For each step write **pass / fail**; for a fail attach a screen recording and the controller
  `app.log` around it.

## 1. macOS — the menu appears in the system menu bar and works

1. Launch the macOS build. In the Apple/system menu bar at the top of the screen, confirm a
   **"Session"** menu with exactly: **Settings**, **Disconnect / End Session**, **Check for
   updates** — and nothing else of ours. Confirm the standard **ShareCtrlScreen** app menu (with
   **Quit ⌘Q**) is still present. **pass/fail**
2. Click **Session → Settings** (while idle, and again mid-session). The Settings modal opens, the
   same as clicking the gear button. Mid-session the video is taken down first so the modal shows
   over it; closing Settings brings the video back. **pass/fail**
3. Start a viewer session, then click **Session → Disconnect / End Session**. The session ends and
   the UI returns to the ready screen, exactly like the on-screen **End** button. **pass/fail**
4. Click **Session → Check for updates**. Settings opens, the Updates panel is scrolled into view
   and a check runs (either "up to date" or an available version). **pass/fail**
5. Confirm **⌘Q** still quits the app (the standard app menu is intact). **pass/fail**

## 2. Linux — the menu appears in the window and works (X11 and Wayland)

1. Launch the Linux build (X11). Confirm an in-window menu bar with the **"Session"** menu holding
   the same three items. **pass/fail**
2. Repeat steps 1.2–1.4 (Settings opens; Disconnect ends a session; Check for updates opens
   Settings/Updates and checks). **pass/fail**
3. Repeat on **Wayland** (GNOME, and KDE/Sway if available). **pass/fail**

## 3. The top-edge drawer is gone on macOS + Linux

1. In a live viewer session (video filling the window), slowly push the pointer to the **very top
   edge** of the video and hold it there. Confirm the picture does **not** shrink and **no** web
   toolbar strip slides in. **pass/fail**
2. Flick the pointer up and out through the top edge repeatedly. Confirm nothing toggles / the
   picture never jumps. **pass/fail**
3. Confirm the video still fills the window and presents normally (no black strip at the top or
   bottom, no misaligned picture), including after opening and closing Settings. **pass/fail**

## 4. macOS — the OS cursor returns the instant the pointer leaves the window

1. Connect **with control** from the Mac; move the pointer over the video. Confirm the Mac arrow
   disappears and only the drawn remote cursor shows. **pass/fail**
2. Move the pointer **off the video and out of the ShareCtrlScreen window** onto the Mac desktop /
   another app — **without** Cmd-Tabbing away. Confirm the normal Mac arrow is back **immediately**
   (it is not stuck hidden). **pass/fail**
3. Move back over the video: the arrow hides again; leave again: it returns. Repeat quickly a few
   times — it must never stick hidden. **pass/fail**
4. Connect **view-only** (no control): the Mac arrow is **not** hidden over the video. **pass/fail**
5. Regression (D10/D11/D12): the drawn remote cursor still tracks your pointer smoothly on a
   high-RTT link; a static host screen still repaints; opening and closing Settings still returns
   the video instantly. **pass/fail**

## 5. Windows is unchanged (regression)

1. Launch the Windows build. Confirm there is **no** native menu (Windows keeps the web UI only).
   **pass/fail**
2. In a viewer session, push the pointer to the top edge: the **existing web drawer still reveals**
   exactly as before (the picture shrinks, the toolbar slides in, moving back down hides it).
   **pass/fail**
3. Windows cursor behaviour while controlling is unchanged. **pass/fail**
