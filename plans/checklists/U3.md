# U3 — Linux .deb/.rpm install can't self-update (tester checklist)

Fixes the raw Tauri error **"invalid updater binary format"** seen when a `.deb`/`.rpm`
install tries the in-app update. The feed (`latest.json` `linux-x86_64`) serves the
AppImage only, so a packaged install downloads a payload whose type does not match the
install and the plugin rejects it. U3 detects a packaged Linux install at runtime
(running-from-AppImage only when `$APPIMAGE` + `$APPDIR` are set AND our own
executable lives under `$APPDIR`, mirroring autostart's containment check — so a
`.deb` launched from inside another AppImage, which inherits `$APPIMAGE`, is still
treated as packaged) and offers a **Download update** link to the releases page
instead of ever calling the installer. AppImage, Windows and macOS are unchanged.

Needs (same as U1): a **published, updater-enabled** release to check against, ideally a
newer one so an update is actually "available". The affordance (Download vs. Update &
restart) shows as soon as a newer version exists on the feed.

## Proven in the lane (no device)

| Check | Where |
|---|---|
| `update_capability` unit tests: linux+appimage → SelfInstall; linux+!appimage → ManualDownload; windows/macos → SelfInstall regardless | `app/src/updater.rs` tests (windows + wsl lane runs) |
| `install_should_proceed` guard: false for ManualDownload, true for SelfInstall (the `updater_install` early-return) | `app/src/updater.rs` tests |
| Whole workspace compiles + clippy `-D warnings` + tests on Windows AND x86_64 Linux (the `cfg(target_os="linux")` appimage path + the `open` crate) | lane `U3` windows + wsl results |
| `cargo build -p app` smoke and `cargo deny check` (the new `open` dep licence) stay green | lane `U3` windows result |

## Device steps

Install the build the way each row says, make sure a newer version exists on the
`latest.json` feed (or the same version to just confirm the affordance/no-error), then:

| Step | Install | Action | Must see |
|---|---|---|---|
| 1 | **Ubuntu `.deb`** (`sudo dpkg -i …` or `apt install ./…deb`) | Settings → **Updates** → Check for updates | the available version + notes, a **Download update** button, and the line "Your install is a .deb/.rpm package; download the latest from the releases page (or use the AppImage for automatic updates)." — and **no** "invalid updater binary format" anywhere |
| 2 | Ubuntu `.deb` | click **Download update** | the system browser opens `https://github.com/yanivkalfa/shareCtrlScreen/releases/latest`; the app does not try to install anything and shows no error |
| 3 | Ubuntu `.deb` | (sanity) there is **no** "Update & restart" button in the panel | only the Download affordance is shown |
| 4 | **Fedora `.rpm`** (`sudo rpm -i …` / `dnf install ./…rpm`) | repeat steps 1–2 | same as the `.deb`: Download link, opens Releases, no raw error |
| 5 | **Linux AppImage** (run the `.AppImage` directly) | Settings → Updates → Check → **Update & restart** | unchanged from U1: downloads, installs, relaunches on the new version; the Download-update text is **not** shown |
| 6 | **Windows** (NSIS install or portable) | Settings → Updates → Check | unchanged from U1: the **Update & restart** button, no Download-update text; the mid-session relabel still reads "End session & update" |
| 7 | **macOS** (DMG) | Settings → Updates → Check → Update & restart | unchanged from U1: replaces itself in place and relaunches |

Report back: Linux packaging kind (`.deb`/`.rpm`/AppImage) and whether the raw
"invalid updater binary format" ever appeared (it must not on `.deb`/`.rpm`); whether the
Download link opened the browser at the Releases page; and that the AppImage, Windows and
macOS update panels behaved exactly as before (U1).
