# W4 — Windows installer sets up the SYSTEM service (tester checklist)

Needs: a real Windows 10/11 host (NOT a CI runner — the runner has no interactive
console session, so the "host appears / tray" steps cannot be judged there), an
administrator account, and a second machine (or the same one) to connect from as the
viewer. Build the installer with `native/scripts/release-dry-run.sh windows` (or take the
`ci-windows-installer` artifact from the `windows-installer` CI job). The SmartScreen
warning on first run is expected (unsigned build): **More info → Run anyway**.

The service name is `ShareCtrlScreenHost`. Inspect it with `sc query ShareCtrlScreenHost`,
`services.msc`, or Task Manager → Services. The host app writes `app.log` in
`%APPDATA%\ShareCtrlScreen`; a launch that defers to the running host writes
`app-handover.log` beside it.

Scope note (decision 2026-11-02): W4 proves the installer **sets up, upgrades and removes
the service** and the **one-instance** rule. Whether the service-run host can see or control
a UAC prompt / the lock screen is **out of W4's scope** (it is tracked separately) — do not
fail W4 on that. Steps 7–8 record what happens there only as information for that other work.

| Step | Action | Must see |
|---|---|---|
| 1 | Fresh install: run `ShareCtrlScreen_<v>_x64-setup.exe`, accept the one UAC consent | installs without a second prompt; the details pane shows `ShareCtrlScreen service: register and start the service` and a success line |
| 2 | `sc query ShareCtrlScreenHost` | `STATE : 4 RUNNING`. `sc qc ShareCtrlScreenHost` → `START_TYPE : 2 AUTO_START`, `BINARY_PATH_NAME` = `"C:\Program Files\ShareCtrlScreen\sharectrl-service.exe" --run-service`, `SERVICE_START_NAME : LocalSystem` |
| 3 | Open `C:\Program Files\ShareCtrlScreen\` | `sharectrl.exe`, `sharectrl-service.exe`, `uninstall.exe`, `THIRD-PARTY-LICENSES.html` all present (the service sits next to the app) |
| 4 | Confirm the host is running: Task Manager → Details, and `app.log` | one `sharectrl.exe`; `app.log` says `started by the ShareCtrlScreen service as this session's host`. The window is minimized (not thrown in your face) |
| 5 | One instance: double-click `C:\Program Files\ShareCtrlScreen\sharectrl.exe` | NO second `sharectrl.exe` starts; the existing window comes to the front; a new `app-handover.log` says it asked the running host to show its window and exited |
| 6 | Start-with-Windows: open Settings in the app, check "Start at sign-in" | it may be shown on, but **no** `ShareCtrlScreen` value under `HKCU\…\Run` (`reg query "HKCU\Software\Microsoft\Windows\CurrentVersion\Run" /v ShareCtrlScreen` → not found): the service is the autostart, so the Run entry is not written |
| 7 | (info only, out of W4 scope) From the viewer, connect and trigger a UAC prompt on the host | record whether the prompt is visible / controllable; **not** a W4 pass/fail |
| 8 | (info only, out of W4 scope) Lock the host (Win+L) with a user still logged in | record whether the viewer sees/controls the lock screen; **not** a W4 pass/fail |
| 9 | Upgrade: bump the version, rebuild, run the new installer over the running install (one UAC consent) | details pane shows the service stopped before files are replaced and started after; `sc query` → RUNNING again; the service's PID in Task Manager has **changed** (it was restarted, not left stopped) |
| 10 | Fast user switch (if two accounts): sign in as a second user without signing the first out | each session gets its own host (`Local\` marker is per session); neither double-starts |
| 11 | Uninstall: Settings → Apps → ShareCtrlScreen → Uninstall (or run `uninstall.exe`) | `sc query ShareCtrlScreenHost` → `1060` (does not exist); `C:\Program Files\ShareCtrlScreen\` is gone; no `sharectrl.exe` left running |
| 12 | Manual-install path: on a clean machine, drop the standalone `sharectrl-service.exe` next to a portable `sharectrl.exe`, run `sharectrl-service.exe --install-service` from an elevated prompt | prints `service 'ShareCtrlScreenHost' registered (…) and running`; `sc query` → RUNNING. `--uninstall-service` removes it |
| 13 | Error surfacing: run `sharectrl-service.exe --install-service` from a **non-elevated** prompt | exits non-zero with a message that it needs administrator rights (not a silent no-op) |

Report back: Windows edition and version, and any step where the service was left stopped,
a second host started, the Run entry appeared while the service was installed, the upgrade
did not restart the service, or uninstall left the service or folder behind. Steps 7–8 are
hand-off notes for the separate elevated-desktop work, not W4 results.
